## 0. 요약 (TL;DR)

- **장서 데이터:** 서가 59권 중 **41권 ISBN 확보** (69%). 나머지는 정보나루 API의 구조적 한계(2016년 등록일 하한) + 책등 OCR 제목의 축약/절판 때문.
- **인식 파이프라인:** 직접 학습한 **YOLO 2클래스 검출기(best.pt)** + 사전학습 **PaddleOCR** 를 결합한 **이중 인식(청구기호 + 제목)**.
- **인식 결과:** 41권 카탈로그 기준 **35/41권 인식(85%)**. 청구기호 단독(22권) 대비 제목 보강으로 크게 향상.
- **오배열 판정:** 현재 22~25%로 나오나 **거짓양성 포함** → 정밀화 필요.
- **[07-06 야간 업데이트] OCR 정밀 진단·후처리 개선:** 오독의 진짜 원인은 OCR 성능이 아니라 **검출 박스가 이웃 라벨 2개에 걸치는 문제**로 판명. 크롭 개선은 역효과(기각), **후처리(잡음 제거→하단 우선→카탈로그 제약→전역 단조 배정)** 로 **59권 중 41권 인식(기존 30권), 오배열 의심 25%→9%** 달성. 재학습·모델 교체 없이 무료 개선. → §3-1
- **대림 확장:** 서가 이미지 라벨링 데이터 + 장서 카탈로그가 핵심. 유사 서가면 인식 **80~90% 기대**.

## 1. 장서 데이터 확보 결과 — 왜 41권인가?

목표: shelf_4558의 뉴턴 하이라이트 59권(청구기호 408-뉴88-N)에 대한 장서 데이터(ISBN·서지) 확보.

### 결과
| 상태 | 권수 | 설명 |
|---|---|---|
| ✅ 확보 (신뢰) | 36 | 제목 정확 일치 |
| ⚠️ 확보 (검토) | 5 | 제목 변형 보정 |
| ❌ 미확보 (절판) | 6 | 실제 제목은 앎, 네이버 DB에 없음 |
| ❌ 미확보 (미상) | 12 | OCR 제목 애매 + 94/95/96권은 제목 자체 미상 |
| **합계** | **59** | **확보 41 / 미확보 18** |

### 왜 정보나루로 직접 못 가져왔나 (핵심 원인 3가지)

1. **등록일 하한 2016-01-01** — 정보나루 `itemSrch`는 2016년 이후 등록 장서만 반환. 뉴턴 하이라이트 세트는 대부분 **2016년 이전 등록**이라 신원도서관 장서인데도 API에 안 나옴. (전체 스캔 결과 뉴턴 관련 10건 중 이 서가와 겹치는 건 1권뿐)
2. **키워드 검색 미지원** — `itemSrch`는 제목/키워드 필터가 안 됨. 전체 7.7만 건을 받아 로컬 필터링해야 하고, deep offset에서 504 오류 + 1일 500건 요청 한도.
3. **책등 제목의 한계** — 서가 목록의 제목은 **책등 사진 OCR에서 뽑은 축약/변형본**(예: "물의 사이언스", "인체Ⅱ 해부학")이라 서점 공식 제목과 글자 단위로 안 맞음 → 자동 ISBN 매칭이 어려움.

### 대안으로 쓴 방법
- **네이버 책검색 API**로 제목 → ISBN 변환
- **알라딘 뉴턴 하이라이트 시리즈 페이지**(140종)에서 공식 제목을 수집해 서가 제목과 대조 후 재검색
- 이 조합으로 41권까지 채움. 나머지는 절판(네이버 부재)이거나 제목 자체가 미상.

> **교훈:** 오래된/절판 시리즈는 정보나루·서점 API만으로 100% 자동 매칭이 어렵다. 최종 확인은 실물 책등 대조가 가장 확실.

## 2. 샘플 테스트 — 사용 기술 & 방법

shelf_4558.jpg (5712×4284, 서가 사진 1장) 대상.

### 파이프라인 구조
```
① 책등/라벨 검출  →  ② 영역 OCR  →  ③ 장서제약 매칭  →  ④ 순서(오배열) 판정  →  ⑤ AR 오버레이
```

### 구성 모델 (중요 — 학습 vs 사전학습 구분)
| 단계 | 모델 | 역할 | 학습 여부 |
|---|---|---|---|
| 검출 | **YOLO best.pt (2클래스)** | 책등에서 **청구기호 라벨 / 제목 영역** 검출 | ✅ **직접 학습(~1000권 라벨링)** |
| 인식 | **PaddleOCR (korean PP-OCRv5)** | 잘라낸 영역의 **글자 읽기** | ❌ 사전학습 모델 그대로 사용 |

- **"2클래스"는 OCR이 아니라 검출기(YOLO)의 클래스 수**입니다 (class0=청구기호 라벨, class1=제목).
- 글자 인식(OCR) 자체는 재학습하지 않고 공개 모델을 사용.

### 이중 인식(dual) 매칭 로직
- 청구기호 라벨 OCR → 토큰 분해(예: 408·뉴88·27) → **장서 카탈로그에 실재하는 권차만 인정**
- 제목 영역 OCR → 카탈로그 제목과 유사도 매칭
- **청구기호 또는 제목 중 하나라도 맞으면 인식 성공**, 둘 다 맞으면 "이중확정"
- 인식된 책들의 권차 순서를 **LIS(최장증가부분수열)**로 검사해 오배열 판정

## 3-1. OCR 정밀 진단 & 후처리 개선 (07-06 야간 실험)

VLM 서버는 기각하고 **OCR 업그레이드**로 방향을 정한 뒤, 근거 확보를 위해 베이스라인부터 격리 측정했다.

### (1) 베이스라인 진단 — 병목이 정확히 어디인가
정답 라벨 대비 청구기호 OCR을 격리 측정한 결과:

| 항목 | 정확도 |
|---|---|
| 접두어(408/뉴88) 읽기 | **100%** |
| **권차(끝 숫자) 읽기** | **~35%** ← 유일한 병목 |

오독 패턴이 전부 **±1~2 이웃 권차**(43→44,45 / 55→56,57,58)로, 글자 오독(3↔8류)이 아니었다.

### (2) 원인 규명 — OCR이 아니라 "박스 걸침"
라벨 크롭 62개를 격자 이미지로 만들어 육안 검수한 결과:
- **거의 모든 검출 박스에 이웃 책 라벨이 2개씩 포함** → 후보에 옆 책 권차가 섞임 (오독의 정체)
- 숫자 자체는 육안으로 선명 → **화질·OCR 성능 문제가 아님**
- 서가는 실제로 거의 **오름차순 정렬** 상태 → 기존 "오배열 25%"는 대부분 오귀속이 만든 **거짓양성**

### (3) 크롭 개선 실험 — 기각
"권차 영역만 타이트 크롭 + 업스케일" 가설 검증 결과 **오히려 하락**(35%→20~24%). 스티커 위치가 spine마다 달라 숫자가 잘려나감. **전처리(크롭) 방향은 이 데이터에서 기각.**

### (4) 후처리 + 전역 배정 — 채택 ✅
재OCR·모델 변경 없이 **같은 OCR 토큰에 후처리만 교체**:
1. 접두어 파편(08/88/884) 제거 → 2. 하단 우선 추출 → 3. **카탈로그 실재 권차만 인정** → 4. **전역 단조 배정**(서가 정렬성을 활용해 비내림차순 최대 배정을 DP로 선택, 복본 c.2는 2회 허용) → 5. 미배정분 제목 매칭 복구

| 지표 | 기존(match_tokens) | **개선(전역 배정)** |
|---|---|---|
| 59권 중 고유 인식 | 30권 | **41권** |
| 오배열 판정 | 25% (거짓양성 다수) | **의심 5건(9%)** — "확인 필요" 플래그로 제시 |
| 비용 | — | **무료** (재학습·재OCR·모델교체 없음, 온디바이스 유지) |

※ 41권(ISBN) 서브셋 기준으로는 30권으로 집계되는데, 이는 제목 매칭 풀을 59권 전체로 넓히고 순서 위반 배정을 거부한 엄격한 방식 때문 (기존 35/41은 41권 제목만 대상으로 한 느슨한 매칭이라 부풀려진 값).

### (5) 시사점
- **OCR 파인튜닝·CLOVA·VLM 없이도** 후처리만으로 큰 개선이 가능했다 → "장서 카탈로그 제약 + 서가 정렬성"이라는 **도메인 지식이 최고의 무기**.
- 남은 한계: 이웃 오염으로 **같은 권차가 인접 spine 2곳에 배정**되는 사례(복본 허용 규칙의 부작용) → 복본(c.2) 표기 인식 또는 책등 외관 비교로 구분 필요 (다음 과제).
- 시각자료: `out_ondevice/shelf_4558_global41.jpg` (초록=정상, 빨강=확인 필요, 회색=미인식)

## 5. 대출 데이터 연동 아키텍처

### 5.1 대출 데이터가 필요한 이유 — "오배열"이 아니라 "결번 해석"
- 오배열(순서 뒤바뀜) 판정은 **LIS(최장증가부분수열)** 기반으로, **대출 데이터가 필요 없다.**
- 흔한 오해: "2권이 대출로 빠지면 1·3권이 오배열로 뜬다" → **아니다.** `[1, 3]`은 여전히 오름차순이라 순서 위반이 아니며 오배열 0건. **빈자리(gap)는 순서를 깨지 않는다.**
- 대출 데이터의 진짜 용도는 **서가에서 빠진 책(결번)의 원인 판정**이다:

| 책이 서가에 없는 이유 | 판정 | 대출 데이터로 구분 |
|---|---|---|
| 대출 중 | 정상 | 대출 목록에 있음 → OK |
| 분실 / 타 서가 오배치 | ⚠️ 조치 필요 | 대출 목록에 없음 → 실종 |

- 재고 점검 공식: **`서가에 있어야 할 책 = 전체 장서 − 현재 대출 중`** → 이 기대 목록과 실제 검출을 비교해 진짜 실종/오배치를 가려낸다. **대출 데이터 없이는 결번이 정상인지 문제인지 알 수 없다.**

### 5.2 "실시간 대출 데이터 + 온디바이스" 부담 검토
- **부담의 성격 구분:** 무거운 건 **인식(YOLO+OCR, 연산)**이고, 대출 조회는 **가벼운 네트워크 호출**이다. 온디바이스가 힘든 건 추론이지 JSON 조회가 아니다 → 대출 조회 자체는 부담이 아님.
- **실시간(연속) 불필요:** 서가 점검은 이산적 이벤트(스캔 1회). 프레임마다가 아니라 **스캔 시점에 서가 범위 대출 상태를 한 번 배치로** 받으면 충분. 대출 상태는 스캔 주기 대비 천천히 변하므로 **주기적 스냅샷(시간/일 단위)** 으로 족하다.
- **API 현실:** 정보나루 대출 데이터는 집계형이며 **하루(D-1) 딜레이 확정** (광수쌤 실무 확인, 07-06). 실시간 개별 대출 여부는 도서관 ILS가 원천. `bookExist`는 근접하나 **ISBN당 1요청 + 500건/일 한도** → 매 스캔 개별 조회는 한도 초과 위험.
- **D-1 딜레이의 함의:** 오배열 판정에는 영향 없음(순서 기반이라 대출 결번이 순서를 깨지 않음 — §5.1). 결번 판정에서만 "전날 이후 대출/반납된 책"이 오차가 되므로, 결번은 확정이 아닌 **'확인 필요' 플래그**로 제시하는 게 맞다.

### 5.3 권장 구조 (하이브리드)
```
[온디바이스]  서가 인식(오프라인 가능)  ─┐
                                          ├─→  [서버/프록시]  대출 스냅샷 캐시
[결번 대조]  대출 스냅샷과 비교(가벼움) ─┘        (주기 동기화 · API 한도/키 관리)
```
- **인식은 온디바이스에서 오프라인**으로 수행 (네트워크 불필요)
- **대출 스냅샷은 서버가 주기적으로 캐시** → 기기는 서버에 가볍게 질의 (도서관 API 한도·키를 서버가 흡수)
- **대조(결번 해석)는 단순 비교**라 온디바이스에서 즉시. 오프라인이면 온라인 복귀 시 지연 대조(deferred reconciliation)
- 결론: **온디바이스 부담은 없다.** 실제 고려할 것은 네트워크 의존성과 API 한도이며, 서버 캐시 계층으로 해결.

## 5-1. 팀 논의 반영 (07-06): "장서 데이터가 오배열 판정에 꼭 필요한가?"

> 광수쌤 질문: "OCR만 되면 오름차순 규칙으로 오배열을 찾을 수 있는데, 굳이 장서 데이터가 필요한가?"

같은 OCR 결과·같은 배정 알고리즘에서 **카탈로그 제약 하나만 켜고 끄고** 비교 실험했다 (`ordering_vs_catalog.py`):

| | 순서만 (제약 없음) | 카탈로그 제약 |
|---|---|---|
| 배정 | 51/62 | 49/62 |
| **유령책** (실재하지 않는 권차를 정상으로 보고) | **5개** | **0개** |
| 오배열 의심 (거짓 경보 포함) | 9건 | **4건** |

### 답변 정리
1. **순서만으로도 오배열 검출은 가능하다** — 팀원 직관은 유효. 실제로 우리 개선판 알고리즘의 핵심이 "서가는 거의 정렬돼 있다"는 순서 성질이다.
2. **하지만 장서 데이터가 하는 일이 3가지 더 있다:**
   - **OCR 노이즈 필터** — 오독된 숫자가 "실재하는 권차"가 아니면 걸러냄 → 유령책 0, 거짓 오배열 경보 절반 이하
   - **결번(빠진 책) 탐지** — "있어야 할 책" 목록 없이는 정의상 불가능 (도서찾기·분실 탐지의 전제)
   - **탐색 범위 축소로 속도 향상**
3. **⚠️ 단, 장서 데이터가 불완전하면 역효과** — 실제로 이번 신원 테스트에서 발견: `books_4558.csv`에 없는 실물 책(권차 2, 3, 18, 68 등)이 서가에 존재했고, 카탈로그 제약이 이 **진짜 책들을 걸러버렸다**. 순서-only 모드가 이들을 표면화함.
   → **대림 요청사항의 핵심: "촬영한 서가와 1:1로 대응하는 정확·완전한 장서 목록"** (이게 인식률 수치의 신뢰도를 좌우)

### 검증 프로토콜 (광수쌤 제안 공식화)
- **단계 정의:** 1단계 = 책등 검출+OCR(읽기) / 1.5단계 = 장서 매칭(인식) / 2단계 = 오배열·결번 판정
- **일반화 검증:** 서가A 사진으로 학습 → **서가B(학습에 안 씀) 블라인드 테스트**로 단계별 지표 측정
- 단계별 지표: 1단계 = 검출률·권차 판독률 / 1.5단계 = 장서 대비 인식 커버리지 / 2단계 = 오배열 정밀도(플래그 중 진짜 비율)·결번 정확도

### 대림 데이터 수집 가이드 (화요일 촬영용)
**사진 (서가당 5장):**
- 정면 1장 + 좌/우 약 15° 각도 2장 + 좌반/우반 근접 2장
- **청구기호 라벨 숫자가 확대 시 육안 판독 가능**해야 함 (프레임에 책 30~60권 정도, 초점은 라벨 높이에)
- 반사·그림자 최소화, 최고 해상도 원본 전송 (**카톡 압축 주의** — 파일 전송 모드/메일 권장)
- 가능하면 서가 **2개** (하나는 학습, 하나는 블라인드 검증용)

**장서 데이터 (촬영 서가와 1:1 대응):**
- 청구기호 전체(분류-저자기호-권차), 제목, ISBN, **복본 여부(c.2 등)**, 가능하면 촬영일 기준 대출중 표시
- 형식은 CSV/엑셀 아무거나 (청구기호·제목만 있어도 시작 가능, ISBN 있으면 표지 매칭까지 확장)
