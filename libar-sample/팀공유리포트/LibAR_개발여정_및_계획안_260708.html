Part 1. 파이프라인의 개념 — LibAR은 어떻게 책을 읽는가

LibAR의 인식은 사람이 서가를 점검하는 과정과 같은 4단계입니다. 각 단계는 독립된 부품이라, 어느 단계가 병목인지 측정하고 그 단계만 갈아끼우는 방식으로 발전해 왔습니다.

① 어디에 책이 있나 (검출) 색 기반 라벨줄 탐지 + 숫자 앵커('8'=책 1권) → [예정] YOLO26n ② 뭐라고 써있나 (인식) PaddleOCR — 라벨은 파인튜닝 인식기 / 제목은 범용 인식기 (이원화) ③ 어느 책인가 (대조) 글자 조각을 책 단위로 조립 → 장서 목록과 매칭 (분류+저자기호+제목) ④ 제자리에 있나 (판정) 청구기호 배열 순서 검사(LIS) → 오배열 의심 표시 + AR 렌더
핵심 개념 1 — "모델"과 "로직"은 다른 축이다.
②의 OCR은 글자를 조각으로 받아 적는 속기사일 뿐, 어느 조각이 어느 책인지 모릅니다. 그걸 조립하는 ③④가 로직(코드)입니다. 우리 성능 향상의 절반은 모델 학습(파인튜닝)에서, 나머지 절반은 모델을 전혀 다시 학습하지 않고 조립 로직을 고치는 것에서 나왔습니다. (예: 숨어 있던 책 4권 발견 = OCR이 이미 읽어놓은 조각을 올바르게 끊어 읽자 나타난 것)
핵심 개념 2 — 인식의 최종 한계는 픽셀 정보량이다.
라벨 폭 40px(광각)에서는 글자 획 정보 자체가 사진에 없어서, 초해상도 AI 등 어떤 소프트웨어로도 복원이 불가능함을 실측으로 확인했습니다. 반대로 130px+(근접)면 거의 다 읽힙니다. 그래서 운영 시나리오가 "걸으며 스캔(근접) = 정밀 모드, 멀리서 한 컷 = 순회 모드" 2단으로 설계됩니다.
핵심 개념 3 — 두 신호(청구기호+제목)의 상호 보완.
라벨이 뭉개져도 책등 제목은 글자가 커서 살아있고, 제목이 가려져도 라벨은 규격품이라 읽힙니다. 두 신호를 함께 쓰는 '이중 인식'이 광각에서 +20%p를 만들었고, 오탐은 0으로 유지됩니다.

Part 2. 지금까지의 여정 — 병목을 찾고, 부수고, 다음 병목으로

Phase 0

신원도서관 검증 (7/5~6) — "파이프라인이 성립하는가"

한 것: 뉴턴 시리즈 59권 서가 1장으로 최초 엔드투엔드 구축. YOLO 2클래스 검출 + OCR + 권차 매칭.
발견한 병목: 검출 박스가 이웃 라벨 2개에 걸침 → 글자를 잘못 읽는 게 아니라 옆 책 글자가 섞이는 문제.
해법: 후처리 전역 배정(카탈로그 제약 + 순서 단조성) → 인식 30→41권, 오배열 거짓양성 25%→9%.
교훈: VLM 서버·CLOVA 등 대안 비교 후 "온디바이스 OCR + 강한 후처리" 노선 확정.
Phase 1

대림 1차 — 광각의 벽 (7/7) — "일반 서가에서 되는가"

한 것: 실제 대림 서가 광각 7장 + 장서 456권 목록. 신원 학습 YOLO가 라벨 생김새 차이로 전멸(도메인 갭) → 색 기반 검출로 우회, 라벨줄 통째 OCR(스트립 방식)로 문맥 확보.
성적: 8% → 19%(스트립) → 34%(제목 이중 인식). 멀티프레임 7장 합산 고유 52권.
발견: ① 병목 = 라벨 해상도(40px)라는 물리 한계 실측 (전처리·초해상도 전부 기각) ② 대출중인 책 2권이 서가에서 발견 — 장서 데이터와 실물의 불일치를 자동 검출한 첫 사례.
교훈: 촬영 프로토콜(근접·동영상)이 모델 개선보다 효율 3배.
Phase 2

파인튜닝 — 저해상 특화 인식기 (7/7~8) — "40px 글자를 배울 수 있는가"

한 것: 실제 카탈로그 텍스트로 합성 저해상 라벨 5,883장 생성(렌더링→축소→블러→압축 열화) → 한국어 인식기 파인튜닝(Colab GPU).
성적: 동일 광각 사진에서 청구기호 판독 6% → 30% (5배). 근접에서는 자모(ㄷ/ㅍ/ㅇ)까지 보정 규칙 없이 직독.
추가: 파인튜닝 모델이 큰 글자(제목)에선 퇴화 → 이원화(라벨=파인튜닝/제목=범용)로 광각 52%.
교훈: 실물 데이터 없이 합성만으로도 5배 — 실전 페어 데이터로 2차 파인튜닝하면 추가 상승 여지.
Phase 3

구조 신호 — 숫자 앵커와 로직 정밀화 (7/8) — "권수를 틀리지 않을 수 있는가"

한 것 (팀 아이디어): 색깔 라벨 위 큰 숫자('8') = 책 1권이라는 물리 앵커 도입 — 붙은 얇은 책 분할, 글자 미판독 책 자리 확보, 권수의 물리적 근거. + 한글 서가 배열 규칙 구현(자모 분해 정렬, 커터 번호 소수 비교), 중복 배정 제거, 잘린 라벨줄 복구.
성적: 근접 권수 74/74 = 100%, 매칭 94%, 광각 1장 63권(라벨줄 3개), 실물 오배열 3건 검출 (권차 역순 포함 — 광각 3m 거리에서도 동일 검출), 장서 DB 이상 6건(목록 부재 4 + 중복 등록 2쌍).
일반화 준비: 라벨 색 자동 감지(5색 후보) + 분류번호의 카탈로그 기반 판정 → 600/700번대 사진이 오면 즉시 검증 가능.

Part 3. 앞으로의 계획 — 대림도서관 전체를 인식하는 LibAR까지

✅ 완료 (7/8)

M1. 측정 완결 + 온디바이스 관문 통과

결과: ① 광각 7장 멀티프레임 합산 → 고유 102권(~73%), 2프레임 이상 안정 77권 — 프레임마다 읽는 책이 달라 단일 63권에서 +39권. 실물 오배열 3건이 투표 최다득표로 검출(1표짜리 오독은 투표로 자동 필터), 대출중인데 서가에 있는 책 2권 발견. ② 파인튜닝 인식기 ONNX 변환·검증 통과 — 청구기호 토큰 93% 완전일치, 크롭당 6ms(CPU) → 라벨 140개 배치 인식도 1초 미만, 폰 단독 구동의 기술 리스크 해소. ③ 2차 데이터 요청 발송 완료(도착 대기).
의미: "한 서가 기준 성능" 공식 수치 확보 + 멀티프레임(=동영상 스캔, M4)의 효과를 수치로 선검증.
다음 · 2차 데이터 도착 후 (~1주)

M2. 일반화 검증 — "800번대만 되는 것 아니냐"에 대한 답

방법: 600/700번대(다른 색 라벨) 근접 사진에 현 파이프라인 적용. 색 자동 감지·카탈로그 기반 분류 판정은 이미 구현됨 → 깨지는 지점만 수리. 해당 구간 장서 목록으로 채점.
기대효과: "대림 전체 적용 가능" 주장의 실증 근거. 공모전 심사 기준(활용성·확산 용이성)의 핵심 방어 논리.
~2주

M3. 학습의 세대 교체 — 휴리스틱을 신경망으로

방법: ① YOLO26n 라벨 검출기: 지금까지 파이프라인이 검증한 라벨 박스(자동 라벨링)로 학습. 색·기울기·조명 휴리스틱이 하던 일을 학습된 검출기가 대체 — 맞닿은 스티커, 기운 각도, 색 변화에 강건. NMS-free 구조라 밀집 책등에 유리하고 온디바이스 최적화 모델. ② OCR 2차 파인튜닝: 같은 단의 근접(정답)+광각(저해상 견본) 페어로 실전 학습쌍 자동 수확 → 합성 데이터의 한계(실제 광학 열화)를 보완. 찍을수록 학습쌍이 쌓이는 자가 개선 루프.
기대효과: 광각 각도 사진(현재 검출 붕괴) 커버, 광각 인식률 52% → 65%+ 목표. 검출 속도 수십 배(온디바이스 요건).
~3주

M4. 동영상 걷기 스캔 — 운영 시나리오의 완성

방법: 서가 앞을 지나가는 30초 동영상에서 프레임 추출 → 프레임 간 투표(멀티프레임은 이미 검증됨) + 트래킹으로 같은 책 중복 집계 방지. 걷기 = 모든 단을 근접 거리에서 통과하므로 정밀 모드가 기본이 되는 촬영 방식.
기대효과: "서가 한 줄 = 30초 산책"이라는 사용자 경험 실증. 근접 94% 성능을 전 단에 적용하는 현실적 경로.
~4주+

M5. 온디바이스 PWA — 폰에서 실시간으로

방법 (PRD 확정 아키텍처): YOLO26n ONNX + 파인튜닝 인식기 ONNX를 브라우저(onnxruntime-web, WebGPU)에서 구동. "검출 1회 + 크롭 배치 인식" 구조(실측 근거: 크롭마다 전체 파이프라인 재실행 시 56분 → 구조 교체로 초 단위). 카메라 스트림에 AR 오버레이(초록=찾는 책/빨강=오배열), 매칭·순서 판정 로직은 JS 포팅(순수 로직이라 이식 용이).
기대효과: 서버 0원, 설치 0회(PWA), 기존 라벨 그대로(태그 부착 불필요) — RFID 로봇(관당 수천만 원) 대비 추가 하드웨어 0원으로 오배열 점검. 경쟁 사례(교세라 SHELF EYE) 대비 실시간 AR + 이용자 모드 차별화.
공모전 제출

M6. 데이터 매쉬업 — 인식을 "도서관 데이터 활용"으로 완성

방법: 스캔 로그(오배열·미배가 이력) × 정보나루 대출 빅데이터 결합 — "대출 회전율 높은 구간일수록 오배열 빈발" 같은 상관 분석 → 점검 우선순위 예측 대시보드. 이미 실증된 재료: 대출중인데 서가에 있는 책 검출(데이터-실물 불일치), 장서 DB 중복·누락 자동 발견.
기대효과: LibAR = 인식 도구를 넘어 장서 운영 최적화 + 장서 DB 품질 검사기. 공모전 주제(도서관 데이터 활용)와의 직결점이자, 1,576개관 확산 시나리오의 근거.
