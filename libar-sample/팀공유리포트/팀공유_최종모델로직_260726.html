1. 큰 그림 — 사진 한 장이 판정이 되기까지

📷 카메라/사진 │ 라이브면: 화면 안정 감지 → 그 순간만 고해상 원샷(2560px) 촬영 ▼ ① 라벨 검출 (YOLO) 책등에서 청구기호 라벨 위치를 찾는다 ▼ 줄(칸) 클러스터 라벨들의 세로 위치로 "같은 줄" 묶기 → 줄별 띠(스트립)를 3배 확대 ▼ ② 글자줄 검출 (OCR det) 확대된 띠에서 글자 줄만 오려낸다 ▼ ③ 청구기호 인식 (OCR rec) 글자를 텍스트로 — "511.4 가68ㄴ" ▼ ④ 장서 대조 (매칭 로직) 읽은 텍스트를 장서 목록 20,944권과 대조해 "어느 책인지" 확정 ▼ ⑤ 순서 판정 (LIS) 같은 줄 책들의 배열 순서를 분석 → 🟢제자리 🔴잘못 꽂힘 ⚪다시 확인

①~⑤ 전부가 폰 브라우저 안(ONNX Runtime Web)에서 돕니다. WebGPU 지원 폰은 GPU로, 아니면 WASM(CPU)으로 자동 전환. 서버 호출이 0회라 와이파이 없는 서가에서도 동작하고 이용자 사진은 폰 밖으로 나가지 않습니다.

2. 최종 모델 3개 — 그리고 왜 이것들이 살아남았나

단계모델크기출신
① 라벨 검출YOLO26n v3 (best.onnx, 동적 입력)11MB 대림 서가 사진 206장·7,039박스 직접 학습 (자동 라벨 부트스트랩 → 사람 검수)

③ 청구기호 인식한국어 rec v4 (fp16)48MB저해상 라벨 데이터로 직접 파인튜닝 — 광각 판독 6%→30% (5배)
기각의 기록이 곧 최종 선택의 근거입니다. 더 좋아 보이는 후보를 총 7번 만들어 전부 실측으로 떨어뜨렸습니다.
  • 인식 모델 v5·v6·v7·v8 — 4연속 기각. 현장 조각 소급 정답(v5) → 정답 순도 강화(v6) → 사람이 직접 라벨(v7) → 고해상 원샷 재료(v8)까지 갔지만 매번 기존 v4보다 일부 지표가 퇴화. 결론: 성능의 남은 병목은 모델이 아니라 입력 픽셀과 후처리 로직. 이후 개선은 전부 로직에서 나왔습니다.
  • 검출기 v4·v5 기각. 검출 지표(재현율)는 올랐지만 최종 판독 권수(E2E)가 오히려 줄어 탈락. 교훈: 모델 교체 판정은 중간 지표가 아니라 끝단 결과로.
  • 초해상(SR)·전처리 기각. 40px 라벨은 소프트웨어로 구제 불가 — 대신 "판독 순간만 고해상 원샷" 전략으로 해결.

3. 매칭 로직 — "읽은 글자"를 "어느 책"으로 확정하기

OCR은 완벽하지 않습니다. 매칭 로직이 오독을 구제하되, 엉뚱한 책을 데려오지는 않도록 단계별 신뢰도와 안전장치를 둡니다. (파이썬 파이프라인과 앱 JS가 동일 로직 — 골든 테스트 144케이스로 항상 일치 검증)

단계하는 일신뢰도
정규화유니코드 통일, 자주 헷갈리는 글자 교정표(0↔ㅇ, 기↔ㄱ 등), 권차(v.N) 토큰 분리—
직독 일치분류번호+저자기호가 카탈로그와 정확히 일치1.0
권차 판별복본·시리즈(v.1/v.2)의 다의성은 권차 숫자로 가른다 — 걷기 판독률 89→99%를 만든 수술1.0
첫 글자 구제저자기호 첫 글자만 오독(상↔싱)이면 나머지 완전일치·유일할 때만 인정0.95
저자 폴백분류번호를 못 읽었을 때 저자기호만으로 전 장서 검색 — 아래 게이트 2중 통과 필수0.9

폴백의 안전장치 2중

  • 분류 유사도 게이트: 읽힌 분류번호와 매칭된 책의 분류가 닮아야(≥0.7) 인정 — 가까운 오독(573.53→673.53)은 살리고 남의 구간(004↔813)은 차단.
  • 행 문맥 게이트 (v1.2 신설): 같은 줄에서 확실히 읽힌 책들의 분류에서 ±10 넘게 동떨어진 폴백 매칭은 확정하지 않고 ⚪보류. 실제 현장 사례 — 511.1813-임82ㄴ이 첫 글자 오독으로 182.2-양82ㄴ(남의 구간)에 매칭돼 가짜 오배열 경보를 울렸던 것을 차단합니다. 글자 하나의 오독이 빨간 경보가 되지 않게.

4. 오배열 판정 — LIS가 "누가 범인인지" 짚는 법

서가의 올바른 배열은 청구기호 오름차순입니다. 같은 줄에서 읽어낸 책들을 왼쪽부터 나열했을 때, "순서가 유지되는 가장 긴 흐름(LIS, 최장 비감소 부분수열)"을 찾으면 — 그 흐름에 끼지 못하는 책이 바로 순서를 깨뜨리는 책입니다. 예를 들어 하17 → 하66 → 하27 → 한65에서 가장 긴 정상 흐름은 하17→하66→한65이고, 하27만 밖에 남으므로 🔴.

  • 정렬 비교는 사전이 아니라 서가 규칙으로: 분류번호는 소수(511.4 < 511.1813 아님!), 한글 저자기호는 초성·중성·종성 분해 비교(글<기<길), 커터 번호도 소수(295<58), 권차는 숫자.
  • 플래그는 직독(청구기호로 확정된 책)만: 추측성 매칭엔 경보를 걸지 않습니다.
  • 근거 제시: 🔴를 탭하면 "지금 꽂힌 곳 A↔B 사이 / 올바른 자리 C↔D 사이"를 보여줍니다 — 사서가 판정을 검증할 수 있어야 신뢰가 쌓입니다.
  • 위험군 제목 대조: 라벨만으로 헷갈리는 413권(전체 2% — 권차 시리즈·유사 기호쌍)만 책등 제목을 추가로 읽어 교차 확인. 보수 설계라 미발동 시 결과 무변화.

6. v1.2에서 다듬은 사용 경험

  • 셔터 판독: 안정되면 자동으로 찍고, 찍힌 화면 위에 진행 표시("📸 폰을 내려놔도 돼요") — 검은 화면·멈춤처럼 보이던 문제의 근본 원인(iOS 카메라 재협상 중 캡처)을 수리.
  • 도서찾기 발견 = 정지 사진 핀: 찾는 책이 발견되면 그 장면에서 멈추고 사진 위에 📍 — 폰을 내려도 핀은 사진 속 그 자리. 찾기 중엔 오배열 경보·사서 버튼이 없는 이용자 전용 화면.
  • 블랙아웃 자가 복구: iOS가 카메라를 검게 방치하면 4초 안에 감지해 스스로 재연결.
  • 기록 루프: 점검 리포트 zip → 드라이브 → 사서 PC에서 dash_build.py로 SQLite 적재 + HTML 대시보드(KPI·분류대별·일자별·오배열 목록) 생성. 전 과정 오프라인.
