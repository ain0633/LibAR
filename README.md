# LibAR — 도서관 빅데이터 × 책등 인식 기반 실시간 AR 서가 관리·탐색 시스템

스마트폰 카메라로 서가를 비추면, AI가 책등을 탐지하고 청구기호를 판독하여
**사서에게는 오배열 도서(빨강)를, 이용자에게는 찾는 책(초록)을** 화면에 실시간 표시하는 웹 서비스.
축적된 오배열 로그를 전국 대출 빅데이터와 결합 분석해 서가 운영을 최적화한다.

> **2026 도서관 데이터 활용 공모전** 출품작 (서비스 아이디어 제안 부문) · 실증 대상: 영등포구립 대림도서관

## 진행 상황 (2026-07-10)

- **근접 촬영 (800번대)**: 권수 파악 100% (숫자 앵커 분권), 목록 보유분 매칭 94%
- **광각 멀티프레임 7장 합산**: 고유 102권 (~73%) — 실제 오배열 3건을 투표 최다득표로 검출, 대출중인데 서가에 있는 책 누적 7권 발견
- **M2 일반화 검증 통과**: 600번대(보라, 수정 0줄)·700번대(검정, 마스크 2줄) — 합산 90권·74권, 새 구간 추가 비용 "0~2줄" 실증
- **온디바이스 관문**: 파인튜닝 rec ONNX — 청구기호 토큰 93% 일치, 크롭당 6ms(CPU)
- **YOLO26n 라벨 검출기 v1**: 자동 라벨 2,071박스 학습(사람 라벨링 0회) — 정밀도 0.86, 휴리스틱이 붕괴한 각도 사진에서 라벨 26곳 검출
- **파인튜닝 3세대(v1·v2·v3) A/B**: 광각 63→65권, 근접은 v1 우위 유지 → 모드별 이원 운용 (근접=v1, 광각=v3). 페어 이식 수확기 완성

## 파이프라인 (현재 실증 구현 기준)

```
사진 → ① 라벨줄 자동탐지 (라벨 색상 5종 × 스케일 자동 선택)
     → ② 숫자 앵커 분권 (라벨 위 숫자 1개 = 책 1권 → 권수 오차 0)
     → ③ 이원화 OCR — 라벨: 파인튜닝 rec / 제목: 기존 rec (한국어 PP-OCRv5)
     → ④ 장서목록 대조 (청구기호 직독 + 제목 이중 대조로 복구)
     → ⑤ LIS 오배열 판정 → ⑥ AR 오버레이 (🟢직독 🔵제목복구 🔴오배열 ⚪미판독)
```

- **라벨 우선(Label-first):** 책 생김새가 아니라 청구기호 라벨을 읽음 → 판본·개정판·커버 변수 회피
- **숫자 앵커:** 색 스티커 위 흰 숫자 하나가 물리적 책 한 권의 표지 — 붙어 있는 얇은 책 분리·미판독 책 자리 확보·권수 검산에 사용
- **이원화 OCR:** 저해상 라벨 전용 파인튜닝 모델(합성 5,883장 학습)과 큰 글자에 강한 기존 모델을 영역별로 나눠 적용
- **이중 대조:** 라벨이 잘리거나 훼손돼도 책등 제목 OCR로 복구
- **LIS 판정:** 인접 비교가 아닌 최소 오배열 집합만 지목 (이웃 오탐 방지)
- **멀티프레임 합산:** 여러 컷의 인식 결과를 투표로 합산 — 인식률 상승(63→102권) + 오배열 오탐 필터
- **적용 범위:** spine-out 단행본 서가 (그림책·비정형 배가는 향후 과제) · 책등/라벨 탐지의 YOLO26n 전환은 로드맵 M3

## 빠른 시작

```bash
cd libar-sample
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt

# 사진·장서 CSV·파인튜닝 모델은 용량 문제로 저장소 미포함 (팀 드라이브 공유)
python daelim_closeup.py <서가사진.jpg> --rec_dir korean_lowres_rec_infer
```

자세한 사용법은 [`libar-sample/README.md`](libar-sample/README.md) 참고.

## 기술 스택

**현재 실증:** Python · PaddleOCR(한국어 PP-OCRv5, 라벨 전용 파인튜닝) · OpenCV · onnxruntime
**목표 서비스:** Next.js PWA · YOLO26n + onnxruntime-web (온디바이스) · Supabase · 도서관 정보나루/국립중앙도서관 Open API · 솔로몬 장서·대출 데이터
